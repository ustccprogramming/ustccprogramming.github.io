# Lab 2：数据类型、格式化输出与浮点数比较

本次实验通过查看类型长度、比较赋值结果和改变输出格式，观察数据在计算机中的表示，并分析浮点数比较时的类型转换与精度问题。

## 1. 基本数据类型的长度

### 题意

没有输入。按 `int`、`short`、`long`、`long long`、`float`、`double`、`long double` 的顺序，在一行中输出七种类型所占的字节数，相邻数之间用一个空格分隔。

### 思路

使用 `sizeof(类型名)` 取得类型占用的字节数。`sizeof` 的结果类型是 `size_t`，使用 `%zu` 输出，不需要先定义这些类型的变量。

### 参考代码

```c
#include <stdio.h>

int main(void) {
    printf("%zu %zu %zu %zu %zu %zu %zu\n",
           sizeof(int),
           sizeof(short),
           sizeof(long),
           sizeof(long long),
           sizeof(float),
           sizeof(double),
           sizeof(long double));

    return 0;
}
```

### 点评与易错点

- **类型长度与编译环境有关。** 题目给出的样例是 `4 2 8 8 4 8 16`，自己的运行结果可能不同，应记录实际结果，不能直接打印样例中的七个数。
- 例如，某些 64 位 Windows 编译环境中的 `long` 为 4 字节；本地 Apple Silicon macOS 环境中的 `long double` 为 8 字节。不能仅凭“64 位系统”确定所有类型的长度。
- `sizeof` 给出的是字节数，不是二进制位数。本实验常见环境中一个字节为 8 位。
- `%zu` 与 `size_t` 对应；`%lu` 只有在 `size_t` 恰好是 `unsigned long` 时才匹配，不能作为通用替代。

## 2. 不同类型的赋值

### 题意

将 `123456789 + 1234567890` 的结果分别赋值给 `int`、`float` 和 `double` 变量，按顺序输出三行，分别使用 `%d`、`%f` 和 `%lf`，不输出提示文字。

### 思路

在本题使用的 32 位 `int` 环境中，两个整数字面量都是 `int`，加法先按 `int` 进行，得到 `1358024679`，没有超出 `int` 的范围。随后再把结果转换成接收变量的类型。

在采用 IEEE 754 二进制单精度和双精度的常见环境中，`float` 只有 24 位二进制有效精度，不能精确表示这个整数；`double` 有 53 位二进制有效精度，可以精确表示它。

### 参考代码

```c
#include <stdio.h>

int main(void) {
    int a = 123456789 + 1234567890;
    float b = 123456789 + 1234567890;
    double c = 123456789 + 1234567890;

    printf("%d\n", a);
    printf("%f\n", b);
    printf("%lf\n", c);

    return 0;
}
```

在上述浮点表示和通常的舍入方式下，输出为：

```text
1358024679
1358024704.000000
1358024679.000000
```

### 点评与易错点

- **接收变量的类型不会改变右侧表达式的运算类型。** 即使赋值给 `double`，这里的加法仍然先按 `int` 进行。如果整数加法本身溢出，事后赋值给 `double` 也不能补救。
- 在这个数量级，单精度浮点数相邻可表示数的间隔为 `128`。`1358024679` 舍入为较近的 `1358024704`，因此第二行与另外两行不同。
- `float` 传入 `printf` 时会提升为 `double`，但赋值给 `float` 时丢失的精度不会恢复。
- 在 `printf` 中，`%f` 和 `%lf` 都输出 `double`，默认保留小数点后六位；在 `scanf` 中，`%f` 对应 `float *`，`%lf` 对应 `double *`，不能混用。
- 不要直接写 `printf("%f\n", 123456789 + 1234567890)`。这里传入的是 `int`，与 `%f` 要求的参数类型不匹配，会产生未定义行为。

## 3. short 的格式化输出

### 题意

使用 `%hd` 将 `-1` 和 `-32768` 读入两个 `short` 变量。每个变量分别按 `%hd`、`%hu`、`%hx` 输出，用空格分隔，两行分别对应两个变量。题目规定 `short` 为 16 位，采用二进制补码表示。

### 思路

`%hd` 输出有符号十进制，`%hu` 输出无符号十进制，`%hx` 输出无符号小写十六进制。无符号输出前显式转换为 `unsigned short`，使参数与格式的含义一致。

在题目规定的表示下，`-1` 的 16 位补码是全 `1`，`-32768` 的补码只有最高位为 `1`。转换为 `unsigned short` 后，数值分别为 `65535` 和 `32768`。

### 参考代码

```c
#include <stdio.h>

int main(void) {
    short a, b;

    scanf("%hd %hd", &a, &b);

    printf("%hd %hu %hx\n", a, (unsigned short)a, (unsigned short)a);
    printf("%hd %hu %hx\n", b, (unsigned short)b, (unsigned short)b);

    return 0;
}
```

输入 `-1 -32768` 时，输出为：

```text
-1 65535 ffff
-32768 32768 8000
```

### 点评与易错点

| 原数 | 16 位补码 | 有符号十进制 | 无符号十进制 | 十六进制 |
| --- | --- | --- | --- | --- |
| `-1` | `1111 1111 1111 1111` | `-1` | `65535` | `ffff` |
| `-32768` | `1000 0000 0000 0000` | `-32768` | `32768` | `8000` |

- 相同的 16 位模式按有符号和无符号方式解释，数值可能不同。对于这里的负数，无符号值等于原数加上 `65536`。
- `scanf` 必须使用 `%hd` 并传入变量地址；不能用 `%d` 向 `short` 变量写入数据。
- 传入 `printf` 时，`short` 和这里的 `unsigned short` 会先提升为 `int`；`h` 长度修饰符再要求按相应的短整型转换后输出。
- `%hx` 使用小写字母且不带 `0x` 前缀。不要写成 `%hX` 或 `%#hx`，否则不符合题目格式。
- 输出格式与强制类型转换都不会修改 `a`、`b` 本身的值。

## 4. 实常数与浮点数比较

### 题意

观察题目给出的三段程序，依次判断 `x1 == x2`、`x1 == 0.1` 和 `x2 == 0.1`。其中 `x1` 为赋值为 `0.1` 的 `float`，`x2` 为赋值为 `0.1` 的 `double`。条件成立输出 `1`，否则输出 `0`，三个结果在同一行用空格分隔。

### 思路

无后缀的实常数 `0.1` 默认是 `double` 类型。常见二进制浮点表示不能精确表示十进制的 `0.1`，`float` 和 `double` 保存的是精度不同的近似值。

`float x1 = 0.1` 会将 `double` 常量转换为 `float`。比较时，`x1` 又被转换为 `double`，但此前舍入造成的误差不会消失。`double x2 = 0.1` 则保留该 `double` 常量的值。

| 程序 | 比较表达式 | 原因 | 结果 |
| --- | --- | --- | --- |
| 一 | `x1 == x2` | `x1` 提升为 `double` 后，与 `x2` 的值不同 | `0` |
| 二 | `x1 == 0.1` | `x1` 提升为 `double` 后，与 `double` 常量的值不同 | `0` |
| 三 | `x2 == 0.1` | 两侧保存相同的 `double` 近似值 | `1` |

原程序中的 `fabs(x1 == x2)` 先计算 `==`，得到整数 `0` 或 `1`，再转换为 `double` 并取绝对值。它与直接判断 `x1 == x2` 的真假相同；另外两段同理，因此下面直接使用比较结果。

### 参考代码

```c
#include <stdio.h>

int main(void) {
    float x1 = 0.1;
    double x2 = 0.1;

    int r1 = (x1 == x2);
    int r2 = (x1 == 0.1);
    int r3 = (x2 == 0.1);

    printf("%d %d %d\n", r1, r2, r3);

    return 0;
}
```

在上述常见浮点环境中，输出为：

```text
0 0 1
```

### 点评与易错点

- **题面样例 `1 1 1` 与所给程序在常见 IEEE 754 浮点环境中的结果不一致，应为 `0 0 1`。** 应根据程序的实际比较过程分析，不能为了匹配样例而直接打印三个 `1`。
- 可以用 `sizeof(0.1)`、`sizeof(float)` 和 `sizeof(double)` 辅助观察，常见结果依次为 `8`、`4`、`8`。类型结论来自语言规则；仅凭两个类型的大小相同，不能断定它们是同一种类型。
- 将 `x1` 按 `%.17g` 输出，可观察到约 `0.10000000149011612`；同样输出 `x2`，可观察到约 `0.10000000000000001`。默认的 `%f` 可能把两者都显示为 `0.100000`，显示相同不代表内部数值相同。
- `0.1f` 才是 `float` 常量。在这里改为比较 `x1 == 0.1f`，结果会变成 `1`，因为两侧具有相同的单精度值。
- `fabs(a == b)` 没有比较误差的作用。若要按误差判断两个浮点数是否足够接近，应比较差的绝对值，例如 `fabs(a - b) < 1e-6`；容差应根据数值范围与题目要求选择。
